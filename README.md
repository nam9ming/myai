# 여기:it

안성시민이 공사·행사·교육·지원·생활 정보를 한곳에서 찾고 관심 분야·지역·일정에 맞춰 확인하는 지역정보 서비스입니다. 기존 소상공인용 위치·영업시간 선별 기능은 유지합니다. 초기 검증을 특정 사용자 집단에서 시작하더라도 서비스 대상을 그 집단으로 한정하지 않습니다.

**현행 기준:** 2026-11-16 백엔드 업무지시서와 11월17일 방향·명칭 결정. 저장소명은 `myai`이며 Flutter Web·Dart / Java21·Spring Boot3.5.x·MySQL8.4 / Python3.13을 유지합니다. 이전 소상공인 명세와 현재 구현을 새 시민용 기능의 완료 실적으로 옮겨 세지 않습니다.

## 새 범위와 재사용 기준

서비스 분야는 **교육·배움, 지원·혜택, 행사·문화, 공사·교통, 생활정보**입니다. 이번 버전의 우선 분야·수집처·개인화 규칙·변경 추적 방식은 팀장과 정합니다. 기존 `construction/event/traffic` API를 문서만으로5분야 계약으로 바꾸지 않습니다.

목록·상세·검색과 지역·분야·모집 상태·비용·기간·정렬을 화면별로 합의합니다. 신청 시작/마감과 행사·교육의 진행 일정은 구분하며, 미상 비용은 무료로, 신청 마감은 진행 종료로 처리하지 않습니다. 대상·자격/신청 조건·방법·준비사항·원문과 확인 시점을 제공하고 확보하지 않은 변경 이력을 만들지 않습니다.

원문·AI 원출력·실패·사람 수정 revision·승인·공개 snapshot을 보존하는 기반을 재사용합니다. 기존 5지점·14일·500m·영업시간 계산은 소상공인 기능의 기준이며 시민 전체 탐색의 공통 제한이 아닙니다. 새 경로·필드·상태·분류는 계약 합의와 호환 검증 후 구현합니다.

기존 차별화 후보3개를 수용하는 원칙은 유지하되 정확한 후보명·완료 기준과 AI 분석·개인화·이해 지원·신뢰성 제안을 대조해야 합니다. 구체화 제안을 최종3개 기능으로 바꾸어 쓰지 않습니다.

**기존 기능 조사 → 화면별 API·필드 합의 → 변경 구현 → 프런트 연동 → 명묵의 반복 시나리오 검증 → 백엔드 문제 수정·인계** 순서입니다. 재사용 현황표·API 명세·개발 코드/실행 안내·테스트 데이터/초기화 방법을 전달합니다. 새 AI·평가의 세부 분담과 단계별 완료 예정일은 별도 협의합니다.

관심 저장·개인 설정은 초기에는 브라우저 저장을 기준으로 합니다. 계정 동기화·새 인증·알림 발송을 필수 범위에 자동 추가하지 않습니다. 연령·관심만으로 신청 자격을 확정하지 않습니다.

## 구조와 실행

```text
frontend/            시민용 Flutter 화면·API 연결의 작업 위치
backend/             Spring 공개/로컬 관리 API·MySQL·Python 연결
processing/          Python 추출·근거/보관·기존 시간/거리·평가 도구
contracts/           현재 구현 API/CLI 계약·합성 예제·호환 변경 기준
docs/spec/           현행 설계·재사용/변경 범위·작업·인수 기준
data/public/         검토 후 공개 가능한 교환 자료
data/private/        Git 제외 원문·AI 작업본·DB 백업
evaluation/private/  Git 제외 독립 정답·실제 사용자 평가 기록
```

기존 실행 명령은 [백엔드 README](backend/README.md)와 [Python README](processing/README.md)를 따릅니다. 일반적인 검증 명령은 다음과 같습니다.

```bash
npm run lint
npm test
npm run build
python3.13 contracts/validate_examples.py
python3.13 -m unittest discover -s processing/tests -v
./backend/gradlew -p backend test bootJar
```

Node.js20+·Python3.13과 백엔드 검증용 JDK21이 필요합니다. MySQL 시험은 운영·공유 DB가 아닌 전용 시험 DB에서만 실행합니다. Flutter 실행·빌드 명령은 프로젝트 구현 후 기록합니다. 위 검증은 시민용 신규 기능·실자료 품질·현장 UX 인수를 대신하지 않습니다.

## 통합·자료·운영

개발 기준은 `develop`, 사람 검수한 배포 기준은 `main`입니다. 기능 PR은 검증·리뷰 후 `develop`에 반영하고 병합 완료 브랜치는 정리합니다. `develop → main`은 [PR20](https://github.com/nam9ming/myai/pull/20)에서 별도 검토하며 배포를 뜻하지 않습니다. [협업 규칙](CONTRIBUTING.md)·[에이전트 공통 규칙](CLAUDE.md)을 따릅니다.

공개 조회에서 AI 공급자를 호출하지 않는 기존 구조와 공개/로컬 관리 분리를 유지합니다. 신규 AI 실행 방식은 범위를 정한 후 연결합니다. 실제 작업본·평가·비밀값은 커밋하지 않으며, 실제 서버 경로·프록시·HTTPS·접근/보존 정책은 운영 담당과 합의합니다. 기존 `/myai/team/`은 이전 희망 배포 경로이며 이름 변경만으로 새 운영 경로를 확정하지 않습니다.

기존 실제 처리 기록은 20고유문서·D05 23실행/25시도, 숨김 revision20개입니다. 공식 평가 manifest는 개발3/확인0으로, 수신47건을 고정40문서 평가나 새5분야 실적으로 집계하지 않습니다. 기존 40문서·개발20/확인20·8필드90%·공개 표시100%·사용자6명 목표/최소3명 평가 추진·탐색시간 중앙값20% 목표는 보존하고 새 분야·필드·과제·분모 적용을 합의합니다.

`ai-lounge-infra`의 CI·OpenAI PR 리뷰·Discord·Project·주간 보고 기반을 사용합니다. Node.js는 자동화 전용이고, 큰 PR 자동 리뷰는 앞60,000자 부분 검토입니다. 설정은 [개발 인프라 안내](docs/development-infra.md)를 참고합니다.
