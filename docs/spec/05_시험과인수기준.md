## B. 실제 공지 추출·선별 평가

### 자료 확보와 사건 단위 분할

M01 목표는 실제 공식 공지40건, 개발20·확인20 유지. 원문 버전·고유 게시물ID·사건 관계를 먼저 정리한다. 같은 URL 수정본은 별도 문서로 중복 세지 않고 버전으로 남긴다. 독립 게시물인 재게시·정정은 문서 건수에 구분 보고하되 고유 사건 수를 함께 적고, 자료 채우기용 중복 수집은 하지 않는다.

한 사건의 모든 문서와 한 문서에 같이 담긴 사건들을 연결요소 split_group으로 묶어 한쪽에 배정한다. 세 유형 분포·미상/정정/복수시간의 포함 정도를 먼저 기술한다. **20/20을 맞추기 위해 그룹을 쪼개지 않는다.** 그룹 조합으로20/20이 안 되면 추가 독립 문서를 확보하고 사전에 선택 기준을 기록한다. 그래도 미달이면 실제 건수/분할과 목표 미달을 보고하며 목표 자체를 바꾸지 않는다. 임의 최소 유형 할당을 사후 만들어 유리한 샘플만 고르지 않는다.

개발용에서 규칙·프롬프트·출력 스키마를 확정한다. 확인용 정답은 별도 저장하고 프롬프트 튜닝 담당에게 해설을 제공하지 않는다. 김윤기은 개발용 정답 교차검토를 수행하고, 확인용 정답 교차검토는 최초 평가 전에는 남규민이 맡는 것을 제안한다. 이는 기존 교차검토 원칙을 지키면서 확인 자료 누출을 줄이기 위한 역할 조정안이다. 확인용을 이미 읽고 개선에 사용했다면 blind holdout이라고 부르지 않고 노출 이력을 보고한다.

### 정답표·동일값 판정

강명묵가 원문에서 사건 슬롯과 필드를 작성하고 다른 담당이 원문과 교차 검토한다. 의견 차이는 이유·근거를 남겨 고정한다. AI 결과를 정답으로 복사하지 않는다. 정답 버전·해시·판정 지침을 최초 실행 전에 잠근다.

평가 단위는 **문서 내 사건 슬롯 × 핵심 필드**. 핵심 필드는 ①시작일 ②종료일 ③시작시각 ④종료시각 ⑤장소 ⑥유형 ⑦적용 대상 ⑧예외, 총8종이다. 복수 일정/장소는 각 필드에 정렬된 집합으로 평가하되 occurrence별 결합이 맞아야 한다. 결합이 틀리면 관련 시간/장소 필드 오답. 각각의 부분정확도도 보조 기록하되 90% 분모를 임의로 세분화하지 않는다.

| 필드 | 동일값 판정 |
|---|---|
| 날짜 | 명시/근거 있는 YYYY-MM-DD 값과 날짜 집합 정확 일치. 미상 연도를 생성하면 오답+생성 오류 |
| 시각 | HH:mm 및 다음날 offset 정확 일치. 명시 종일과 미기재 구별. 초가 명시되면 초까지 비교 |
| 장소 | 사전 고정 canonical 이름/주소/구간끝점·정류장 집합 일치. 공백·승인 동의어만 정규화; 임의 가까운 장소는 불일치 |
| 유형 | construction/event/traffic 집합 정확 일치; 추가 유형도 오답 |
| 대상 | 교통 방향·차량·정류장 등 의미 단위가 모두 맞고 없는 조건을 추가하지 않음. 동의어 목록은 평가 전 고정 |
| 예외 | 제외 방향·시간·대상 조건 집합 정확 일치. ‘미기재’와 ‘예외 없음’ 분리 |

사건 슬롯 대응은 원문의 근거 block과 독립 금표의 사건 anchor로 사람이 판정하고 모델에 유리하게 병합하지 않는다. 누락 사건은 그 사건의 정답 있는 필드 전부 오답. 중복 추출은 대응 가능한1개만 매칭하고 남는 항목은 추가/중복 오류. 여러 사건을 합쳐 조건이 뒤섞인 출력은 해당 필드 오답.

### 점수·오류·재시험

`자동 일치율 = 맞은 정답 필드 수 / 정답이 존재하는 핵심 필드 수 ×100`.

원문에 정답이 있는 필드의 null/누락/추출실패는 오답이며 분모에서 빼지 않는다. gold가 not_stated/ambiguous인 필드는 기본 일치율 분모 밖이다. 그곳에 AI가 값을 만들면 생성 오류로 별도 집계한다. gold가 있는 필드라도 근거 밖 조건을 덧붙이면 오답이자 생성 오류로 중복 표기할 수 있다. 필드별 정확도·분모, 문서 처리 실패율, 사건 누락/중복, 생성 오류의 수와 전체 출력 필드 대비 비율도 함께 제시한다. 분모0인 항목은 N/A이고100%로 쓰지 않는다.

구조 재시도는 사전에 정한 동일 정책으로 수행한다. 최초 raw 시도 결과와 최대3회 내 최종 자동 결과를 모두 보고하고, **M02의 기본값은 정책 적용 후 사람 수정 전 자동 결과**로 고정한다. 의미 오류를 정답 피드백으로 재질의한 것은 자동 최초 성능에 넣지 않는다.

같은 확인 문서·정규화 계약으로 단순 규칙 기준선을 실행한다. 기준선은 개발용에서 고정한 유형 키워드·날짜/시간 패턴·검토된 지명 사전·대상/예외 키워드 주변 문장 추출이며 없는 값은 null. 규칙 버전·한계를 기록한다. 비교 결과는 규칙 자동 / AI 자동 / 사람 수정후로 나눈다. AI가 개선한 필드와 악화시킨 필드, 검토에 든 시간도 함께 기술한다.

확인용 최초 결과를 잠근 뒤 발견 오류는 개발용의 별도 유사 사례로 수정한다. 같은 확인 자료 재시험은 `retest`로 표기하며 새 일반화 증거처럼 제시하지 않는다. 확인 자료의 해설로 직접 튜닝했다면 오염된 재시험임을 명시한다. 금표 자체 오류는 수정 전·후 버전과 점수 차이를 모두 남긴다.

### 실제 자료 선별 평가

강명묵·남규민이 기준 지점/영업시간/case별로 기대 후보·확인 필요·취소·제외와 이유를 수동 판정한다. 규칙 엔진에 **금표**, **AI 자동값**, **사람 수정값**을 각각 넣어 엔진 오류와 추출 오류를 분리한다. 장소 미상은 미상 그대로 비교하며 원문에 없는 좌표를 정답으로 꾸미지 않는다. 후보 precision/recall, 확인 필요 적절성, 누락·거짓 포함, 취소 누락을 건수와 함께 보고한다. 후보 정답0이면 recall은 N/A. 별도 새 백분율 목표를 원래 계획처럼 추가하지 않는다.

공개 카드 M03은 실제 공개 snapshot의 candidate·needs_check·cancelled 카드 전체를 분모로 한다. 각 카드에 적어도1개 공식 원문 링크와 성공 확인 시각이 있어야 하며 필드별 출처가 여러 개면 상세에 모두 연결한다. 화면 표시100%와 연결 점검 성공률을 분리한다. 원문 날짜/장소/대상 오류는 공개 전 수정한다.

## C. 사용자 비교 평가

### 모집·조건 고정

사용자6명 목표, 최소3명 평가 추진. 소상공인 우선이며 실제 유형·모집/거절/불참/중단을 기록한다. 전문가1~2명 권장 자문은 별도이며 시민 사용자 수에 더하지 않는다. 비상인의 조작 평가를 상인 실증이라고 표현하지 않는다.

동등 난이도 과제 A/B 두 세트를 만든다. 각 세트에 고객 안내·배달/입고·행사 준비 3문항, 정답 사건 수·유형·예외 난이도·원문 분량을 가급적 맞춘다. 양쪽 방식에는 **같은 전체 공식 자료 집합**을 제공하고 다른 질문을 배정한다. 기존 방식은 공식 게시판/원문과 동일한 위치 참고 자료를 사용, 시제품도 그 집합의 구조화 결과만 사용한다. 비교 대상 밖 자료가 검색되면 별도 표시하고 채점 집합에는 섞지 않는다.

실증 전 팀원이 수행하는 파일럿으로 문항·제한시간·완료 기준을 확정한다. 파일럿 참가자는 본 평가에 중복 산입하지 않는다. 제안 제한시간은 문항당5분, 방식당3문항이며 두 방식 합계 최대30분+동일 조작 안내/인터뷰. 파일럿에서 바꾸면 본 평가 시작 전에 문서 버전으로 고정한다.

| 참여 순번 | 첫 방식·과제 | 둘째 방식·과제 |
|---|---|---|
| 1 | 게시판 A | 시제품 B |
| 2 | 시제품 A | 게시판 B |
| 3 | 게시판 B | 시제품 A |
| 4 | 시제품 B | 게시판 A |
| 5 | 게시판 A | 시제품 B |
| 6 | 시제품 A | 게시판 B |

3명만 참여하면 앞3개 순서를 사용하고 불균형을 한계에 명시한다. 참여 결과를 본 뒤 과제를 바꾸지 않는다. 동일 참여자는 같은 기기·브라우저·네트워크를 사용하고 양쪽 안내 시간을 동일하게 준다. 구체 정답을 미리 알려주지 않는다. 자료 snapshot과 원문 변경 여부는 당일 확인한다.

### 완료·시간·실패 정의

문항 공개 후 시작, 이용자가 답 제출 후 종료. 날짜·장소·적용 대상·예외를 모두 맞추고 관련 사건을 빠뜨리지 않으면 correct. 틀린 제출은 incorrect, 제한시간 도달 timeout, 본인 중단 withdrawn, 기기/연결 불능 technical_failure. 미시작도 기록한다. 중간 정답 피드백·조작 대행은 허용하지 않고 요청/제공 내용을 assistance_notes에 남긴다. 로딩·필터 조작·원문 이동은 시간에 포함한다.

M05 기본 분석은 **세 문항을 양쪽 방식 모두 정확히 완료한 참여자**의 방식별 소요시간 합계 `B_i`, `P_i`를 사용한다. `reduction_i=(B_i-P_i)/B_i×100`, B_i>0. 그 개인별 값의 중앙값이20% 이상인지 본다. 짝수 인원 중앙값은 가운데 두 값 평균. 음수 단축률을 삭제하지 않는다. 유효 인원이0이면 계산 불가, 전체 평가 인원과 유효 인원은 따로 보고한다. 문항 일부만 정확한 개인의 문항별 보조 분석은 가능하나 이를 기본 지표와 섞지 않는다.

실패/중단자의 시간을0 또는 제한시간으로 대체해 기본 단축률에 넣지 않는다. 대신 전체 시작 문항 수 대비 정확 완료율·날짜/장소/대상 정답률·누락 사건 수·거짓 포함·중단·기술 실패를 방식별로 모두 보고한다. 미시작은 모집/배정 분모에도 표시한다. 시제품의 정확 완료율이 낮거나 같은 전체 과제 기준 누락률이 증가하면 시간 목표를 달성해도 개선 성공으로 판정하지 않는다. 작은 표본에서 통계적/전체 상인 효과를 주장하지 않는다.

후속 인터뷰: 편의/유용성/지속 이용 의향 1~5점, 만족/필수 개선 자유 응답. 응답 수·미응답을 표기하고 평균과 개별 분포를 보존한다. ‘확인 필요’ 이해 여부, 직선거리와 실제 통행 영향 구별, 원문을 찾아갈 수 있는지 추가 관찰한다.
