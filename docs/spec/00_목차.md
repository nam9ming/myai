# 여기:it — 설계·개발 명세

갱신일: 2026-11-17 · 팀: 안성맞춘 · 저장소/폴더명: `myai` 유지. 서비스 명칭은 **여기:it**이며 대화의 ‘여기잇’도 같은 프로젝트를 뜻한다.

안성시민 전체가 지역정보를 찾고 대상·신청조건·기간·비용·원문을 이해하도록 돕는다. 분야는 **교육·배움, 지원·혜택, 행사·문화, 공사·교통, 생활정보**다. 기존 소상공인 기능은 유지하되 시범구역·5지점·14일·500m를 시민 서비스 전체의 이용 제한으로 적용하지 않는다. 이번 버전의 우선 분야·실제 수집처·새 계약·단계별 완료 예정일은 팀과 합의한다.

확정 기술은 Flutter Web·Dart / Java21·Spring Boot3.5.x·MySQL8.4 / Python3.13이다. 기존 백엔드·Python·DB는 재사용 기반이며, 새 5분야와 시민용 조회가 구현됐다는 뜻은 아니다. `frontend/`의 추적 파일은 README·TASK뿐이다. 합성 HTML과 [여기:it 웹시제품](https://yeogi-it-neighborhood.kmnam001.chatgpt.site/)은 화면 참고이며 Flutter·실제 공지·기존 API 연동 완료 증거가 아니다.

## v1.1 변경 사항

2026-11-02의 v1.1은 Flutter Web / Spring Boot / MySQL로 기술을 확정한 기록이다. Python AI·계산을 유지하고 공개 API는 Spring이 제공한다. 2026-11-16 업무지시서와 11-17 사용자 결정으로 명칭·시민 대상 범위·현행 담당·작업 순서를 갱신했다. 이전 ZIP·`docs/reference/`·`docs/superpowers/`의 11월2~5일 계획은 당시 근거다. 11/3 인계·11/4 시연은 과거 일정이며 현재 마감 지시가 아니다.

우선순위는 **최신 사용자 명시 결정 → 2026-11-16 백엔드 업무지시서 → 이번에 갱신한 활성 설계/작업 문서 → 이전 계획·프로그램 원자료**다. 실제 연결에는 적용 중인 `contracts/`·코드의 기존 계약을 따른다. 새 설계와 기존 계약이 다르면 문서만으로 JSON을 바꾸지 않고 영향·버전 호환·마이그레이션·시험을 합의한다. 프로그램 제출·권한·운영 사실은 해당 기관 확인으로 구분한다.

기존 R/S/D/I/C/T/W ID는 회귀·추적을 위해 보존한다. 3유형·지점/영업시간 계약과 C01~C10은 기존 기능 기준이다. 새 5분야·시민 조회·필드·화면 인수는 기존 계약과 구별해 읽는다. [05](05_시험과인수기준.md)의 Y01~Y10은 새 범위 인수 초안이며 합의 후 실제 API·화면·자료와 연결한다.

## 인계할 때 지킬 계약

1. 김윤기는 기존 기능 조사→상헌과 화면별 필드/API/오류 합의→변경 구현→프런트 연동→명묵의 반복 시나리오 검증→백엔드 원인 오류 수정 순서로 진행한다. 남규민은 범위·수집처·개인화·변경 추적·일정을 조율한다. 이전 강명묵 백엔드/김윤기 AI 역할은 과거 기록이다.
2. 목록·상세·검색과 지역·분야·모집 상태·비용·기간·정렬을 설계한다. 신청 시작/마감과 진행 일정을 분리한다. 비용 미기재를 무료로, 신청 마감을 진행 종료로 바꾸지 않는다.
3. 대상·자격/조건·방법·준비사항·원문·확인 시점과 확보된 변경 전후를 보존한다. 없는 이력·값은 미확인으로 남긴다. 연령·관심만으로 신청 자격을 확정하지 않는다.
4. 원문·AI 원출력·사람 수정·승인·공개 snapshot과 실패·revision·출처·불확실성·개인정보 경계를 재사용한다. 기존 Python 계산은 단일 원본이며 공개 조회 중 AI를 호출하지 않는다. 신규 AI 방식은 최종 3후보 범위와 함께 합의한다.
5. 관심 저장·개인 설정은 초기 프런트 브라우저 저장 기준이다. 계정 동기화·새 인증·알림 발송은 자동 필수가 아니다. 기존 로컬 관리의 Bearer·loopback·Host·Origin 경계를 유지한다.
6. 기존 40문서/dev20·holdout20/8필드90%/공개 표시100%/사용자6명 목표·최소3명 평가 추진/시간 단축 중앙값20% 목표를 삭제·축소하지 않는다. 새 분야·필드·과제·분모 적용은 별도 합의한다. 처리 건수·기계 검사·합성 회귀를 실제 독립 평가로 세지 않는다.
7. UI는 AI/Figma 시안→검토·피드백→화면 확정→Flutter 구현 순서다. S10은 동등한 로컬 HTML 보고서·명령 방식도 허용하며 별도 관리 UI를 새 필수 인수 조건으로 만들지 않는다.
8. `develop`은 통합, `main`은 사람 검수·배포 기준이다. 단계별 완료일은 담당자와 합의하고 공수·진행률·섭외·성과를 추정하지 않는다.
