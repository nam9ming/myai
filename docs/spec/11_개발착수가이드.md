# 11. 윤기·팀 개발 착수 가이드

갱신일2026-11-17 · 프로젝트 **여기:it** · 저장소/폴더 `myai` 유지. 통합 기준은 `develop`, 사람 검수·배포 기준은 `main`이다. 11/16 백엔드 업무지시서와 최신 사용자 결정에 따라 기존 기능을 조사·재사용·변경한다. 문서·합성 시제품을 새5분야 구현·실제 연동·평가 완료로 표현하지 않는다.

## 확정 사항

- 대상은 안성시민 전체. 교육·배움/지원·혜택/행사·문화/공사·교통/생활정보 5분야를 다루고 기존 소상공인 기능을 유지한다. 초기 검증 집단과 시민 전체 서비스 범위를 구분한다.
- 기술은 Flutter Web·Dart / Java21·Spring Boot3.5.x·MySQL8.4 / Python3.13. Node.js20+는 자동화 전용이다.
- 김윤기: 기존 백엔드 조사·재사용/변경·상헌 화면/API 합의·연동·백엔드 원인 오류 수정.
- 이상헌: AI/Figma 시안 검토·피드백·화면 확정 후 Flutter 구현·API 연결.
- 강명묵: 동일 데이터·초기화·환경의 반복 시나리오 검증·오류 재현·수정 후 재검증.
- 남규민: 우선 분야·수집처·3후보 대응·개인화·변경 추적·일정·평가/운영 범위 조율.
- 이전 강명묵 백엔드/김윤기 AI 배정과11/3 인계·11/4 시연은 과거 기록이다. 현재 단계별 완료 예정일은 팀과 합의한다.

차별화 후보3개는 모두 수용 원칙이며 정확한 명칭·내용은 미제공이다. 정보 분석·개인화·이해 지원·신뢰성4항목은 구체화 제안이고3후보를 대체하지 않는다. 이번 버전의 우선 분야·실제 수집처·신규 AI 실행방식/담당·새 경로/필드/enum은 합의 대상으로 남긴다.

## 첫 연결 순서

1. 김윤기는 기존 기능·브랜치/코드 위치·실행·사용 가능한 API를 조사하고 재사용/수정/추가 표를 작성한다. 기존 백엔드·Python·DB를 빈 프로젝트부터 다시 만들지 않는다.
2. 남규민과 이번 우선 분야·수집처·3후보 대응·개인화·변경 추적을 맞춘다. 상헌과 목록/상세/검색·지역/분야/모집/비용/기간/정렬·필드·오류·미확인 값을 합의한다.
3. 상헌은 AI/Figma 시안 검토→피드백→화면 확정 후 Flutter를 구현한다. 합의한 가상 응답으로 작업 가능하나 합성 시제품과 실제 API 연결 상태를 구분한다.
4. 김윤기는 합의한 백엔드 변경과 필요한 호환 migration·데이터 적용법을 구현한다. 적용된 Flyway·원문/AI 원출력/과거 revision·공개 snapshot을 덮어쓰지 않는다.
5. 상헌과 실제 API를 연결한다. 기존3개 `GET /api/v1/config`, `POST /api/v1/matches`, `GET /api/v1/events/{event_id}?snapshot_id=…`가 새 시민용 검색·필터를 이미 제공한다고 가정하지 않는다.
6. 김윤기는 명묵에게 동일 데이터·초기화·환경·버전·기대 결과를 전달한다. 명묵이 정상/누락/신청마감/진행종료/취소·오류를 반복 검증하고 김윤기는 백엔드 원인 오류를 수정한다. 같은 조건으로 재검증하고 미완료를 남긴다.

[웹시제품](https://yeogi-it-neighborhood.kmnam001.chatgpt.site/)은 합성 공지·원문 예시·기존 백엔드 미연결 화면 참고다. [Figma](https://www.figma.com/design/lM2PFXTrzaJmLqbkVp4gUO)는 검토 대상이며 디자인 내용을 읽거나 확정한 증거가 아니다. 현재 `frontend/`에는 추적된 Flutter 앱 코드가 없고 기존 `npm run build`는 합성 HTML 패키징이다.

## 김윤기 착수·인계

기존 기능 조사는 [백엔드 재사용·변경 표](../../backend/docs/citizen-backend-reuse.md)를 출발점으로 삼는다. Java/DB·Python·보관본/평가·미병합 화면 소비자까지 연결한 코드 근거이며 새 계약의 확정·구현 완료를 뜻하지 않는다.

- 기존 [백엔드 README](../../backend/README.md)의 fixture/public/로컬 관리, DB·계산·import·검토/승인·공개/복구·실행 설정을 읽고 재사용 가능/변경/미확인을 적는다. 실제 키·원문·평가 기록은 공유하지 않는다.
- 새 필드와 기존 D/I/C·DB·import·검토·공개·export·rollback·평가 도구의 영향 범위를 나열한다. 새 API/enum·DB 열은 상헌/남규민과 합의하고 기존 JSON과 호환 변경을 분리한다.
- 신청 시작/마감과 진행 일정을 분리한다. 비용 미기재는 무료가 아니고 신청마감은 진행종료가 아니다. 대상·자격/조건·방법·준비사항·지역·원문·확인시점과 확보한 변경 전후를 보존한다. 없는 값/이력은 미확인이다.
- 연령·관심만으로 신청 자격을 확정하지 않는다. 관심 저장·개인 설정은 초기 프런트 브라우저 저장이며 새 인증·계정 동기화·알림 발송은 자동 필수가 아니다.
- 기존 Python 계산 단일 원본·공개 조회 중 AI 호출 없음·원출력/사람 수정/승인/공개 분리·실패/근거 보존을 유지한다. 새 AI 실행은 최종3후보 범위와 합의한다.
- 기존 로컬 관리 Bearer·loopback·Host/Origin 경계를 유지한다. S10은 동등 로컬 HTML 보고서·명령도 인수 가능하며 새 관리 UI를 필수로 추가하지 않는다.
- 전달물은 재사용 현황표, 합의한 실제 API 명세, 코드/PR·실행/설정/데이터 적용법, 동일 조건 검증 자료·결과·제약·미완료다. 백엔드 원인/수정·명묵 재검증을 연결한다.

기존 T01~T23·C01~C10·DB01~DB11·IN01과 새 Y01~Y10 인수 초안은 별개다.40/dev20·holdout20·8필드90%·공개표시100%·사용자6명 목표/최소3명 추진·시간중앙값20%를 임의 축소하지 않는다. 새 분야·필드·과제·분모 적용은 최초 평가 전에 합의한다. 기존 처리량·합성 회귀는 새 독립 평가 성과가 아니다.
