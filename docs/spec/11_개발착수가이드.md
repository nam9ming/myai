## 첫 연결 순서

1. 이상헌은 공통 JSON을 Flutter asset fixture로 읽어 목록→상세→조건을 연결합니다. 명묵/윤기 작업 완료를 기다리지 않습니다.
2. 강명묵은 동일 예제 DTO로 Spring API3개를 먼저 응답하고 Flutter와 연결합니다. 가상 응답 상태를 명시합니다.
3. 김윤기는 Python 순수 계산+CLI를 같은 계약으로 만들고 강명묵과 한 요청·한 응답부터 연결합니다. 공개 응답 예제를 계산 입력/정답으로 그대로 복사하지 않습니다.
4. 남규민이 전달한 실제 공지를 김윤기가 추출·검토하고, 강명묵이 검토 JSON을 MySQL에 import하여 공개 snapshot을 만듭니다.
5. Flutter의 fixture를 실제 API로 전환하고 같은 조건→목록→상세→원문을 연구실 환경에서 재현합니다.

목록·상세·조건 화면의 실제 코드가 첫 인계물입니다. 디자인 참고 수집·기술 조사·빈 프로젝트만으로 화면 구현 완료를 보고하지 않습니다. 실행 가능한 부분부터 공유하고 미완료·예제/실제·API/DB/Python 연결 상태를 기록합니다.

## 김윤기 착수·인계

- 기존 계획의 C01~C10과 D05/D06을 우선 읽고 Python 환경·의존성을 고정합니다.
- AI 도구 접근·실행 가능 여부와 실제 공지 샘플 상태를 바로 확인합니다. 지원 계정/비용을 확보했다고 추정하지 않습니다.
- AI 원출력과 사람 수정본을 나누고 날짜·시간·장소·대상·예외·근거·미상 이유를 기록합니다. 공사·행사·교통 각1건부터 진행합니다.
- 강명묵과 계산 CLI 입출력·오류·버전·Python 실행 경로를 먼저 맞춥니다. 시간·거리·후보 판정은 Python의 단일 원본입니다.
- 이상헌에게 공개 JSON의 의미·미상·상태를 설명하되 Flutter와 Spring 코드를 별도로 전면 재작성하지 않습니다.
- 전달물: 변경 코드·커밋, Python/도구 버전, 실행 명령, 원출력/검토 JSON, CLI 입력/출력, 실제 실행 건수·시험·미완료.
