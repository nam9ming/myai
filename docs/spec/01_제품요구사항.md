# 01. 제품 요구사항

**여기:it**은 안성시민 전체가 지역 정보를 찾고 자신에게 필요한 조건·일정·출처를 확인하는 모바일 우선 웹앱이다. Git 저장소·폴더명 `myai`는 유지한다. 2026-11-16 백엔드 업무지시서와 2026-11-17 사용자 결정을 현행 범위로 적용한다. 이전 11/3 인계·11/4 시연 계획은 과거 기록이다.

기술은 Flutter Web·Dart / Java21·Spring Boot3.5.x / MySQL8.4 / Python3.13을 유지한다. 이 문서는 제품 요구이며 구현 완료를 뜻하지 않는다. [08 기술 구성](08_기술구성과연결.md), [09 DB 설계](09_DB설계와트랜잭션.md), [10 WBS](10_인원별WBS.md), [인터페이스 기준](../../contracts/README.md)을 함께 확인한다. 기존 S/D/I/C/T·R01~R16 ID는 기존 기능과 시험을 추적하기 위해 보존한다.

## 문제와 검증할 가설

[확정 요구] 서비스 대상은 안성시민 전체다. **교육·배움, 지원·혜택, 행사·문화, 공사·교통, 생활정보**를 제품 범위로 삼고, 이번 버전에서 먼저 구현할 분야와 실제 수집처는 남규민·팀장과 합의한다. 초기 특정 집단의 검증은 가능하지만 전체 대상을 소상공인으로 제한하지 않는다. 공공기관의 공식 서비스가 아닌 안성맞춘팀의 시민 실증 시제품이다.

| 가설 | 확인 방법 | 반대 결과가 나왔을 때 |
|---|---|---|
| H1 여러 게시판에 흩어진 정보를 찾는 데 부담이 있다 | 시민의 최근 탐색 경험·사용 채널·막힌 단계 확인 | 불편이 적었다는 의견도 보고하고 범위·동선 재검토 |
| H2 지역·분야·신청기간·진행일정·조건을 구분하면 확인이 쉬워진다 | 같은 자료·동등 과제의 게시판/시제품 비교 | 속도만 좋아지고 정확도가 떨어지면 성공 주장 금지 |
| H3 AI가 단순 규칙보다 비정형 조건을 잘 추출한다 | 동일 확인 자료의 규칙/AI 자동 결과 비교 | 필드별 열위와 사람 수정 부담 보고 |
| H4 연령·디지털 이용 수준이 달라도 짧은 동선으로 원문에 도달한다 | 모바일·PC의 탐색·필터·조건 이해 관찰 | 막힌 단계·문구·접근성 개선 |

차별화 후보 **3개 모두 수용** 원칙이다. 정확한 명칭·내용은 아직 제공되지 않았으므로 별도 기능으로 추측하지 않는다. 정보 분석·개인화·이해 지원·신뢰성은 구체화를 위한 검토 관점이며 3후보의 대체 목록이나 확정 구현 범위가 아니다. 후보별 입력·출력·근거·실패 대응·평가 과제는 팀장과 합의한다. 수요 규모·품질·탐색시간 개선은 아직 달성 성과가 아니다.
