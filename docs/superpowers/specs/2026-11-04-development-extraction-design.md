## 목적·범위

TASK의 실제 자료 처리 경로를 기존3건에서 확장한다. 원문·실패 원출력을 보존하고 신규 개발용 최대17건의 OpenAI 실행→D05→검증된 D06 숨김 초안을 실제로 연결한다. 결과가 실패여도 분모·원본에 남기며 의미 오류를 자동 보정하거나 새 유료 실행으로 감추지 않는다.

## 선택·자료 경계

- 신규44건의 최종 `current-preparation.json`→`package-v2/`만 읽는다. source SHA는 `eec585520b72a5e7c84ef9691cf78a6dde09c8cc5efea49215b53f65fe065d6e`, 전처리는 `notice-nfc-lf-contact-v2`다. 기존575파일·구3건·stage37 증거·사용자 파일은 수정하지 않는다.
- 외부 전송 전 개인정보 후보·원문/첨부 의존·관계 후보를 점검한다. 인명·개인주소 등 미확정 내용은 전송 보류한다. 공공 행사장/도로 주소는 개인주소와 구별한다. 첨부·이미지는 전송하지 않으며 미수신/ALT·본문 완전성 한계를 그대로 기록한다. 첨부 유무로 쉬운 문서만 선별하지 않는다. 선택/보류를 가르는 중복·재공지 후보 그룹도 보류한다. 이는 사람의 권리 검토 완료가 아니다.
- 남은 문서를 게시일 내림차순·게시 identity 오름차순으로 최대17건 선택하고 UUID·입력 hash·제외 이유를 **첫 호출 전에** 고정한다. 추출 성공 여부로 선택하지 않는다. 대상 부족은 실제 수로 보고하며 임의로 채우지 않는다.
- 선택은 개발 노출 선언이다. 나머지를 blind holdout으로 선언하지 않는다. 실제 dev3/holdout0 manifest와 독립 gold는 유지하며40·20/20·D09 완료로 세지 않는다.

## 접근 방법

기존 Python run/verify/freeze/draft와 Java local-extraction/local-import를 그대로 사용한다. 새 batch API·서비스·의존성은 추가하지 않는다. 모든44건 호출은 평가 후보를 소진하므로 선택하지 않는다. 공개 workflow의 artifact에는 실제 공지를 넣지 않는다. 이 선택과 실행 구성은 기존 자율 진행 위임에 따른 에이전트 판단이다.

## 실행·보존

- 기존 `gpt-6.1-sol`·`prompt-v2`와 요청120초/최대3시도/8192출력을 유지한다. 준비된v1프롬프트를 API 요청으로 사용하지 않는다. 모델 상세 버전·금액/통화 미상은 null이다.
- 기존에 사용자가 지정한 로컬 개발 키는 부모가 실행하는 비공개 프로세스에서만 환경변수로 전달한다. 값·파일 내용·환경 전체를 출력/보관하지 않는다. 다른 에이전트는 키에 접근하지 않는다. GitHub Secret을 추출하지 않는다.
- 사전에 고정한 run_id를 사용하고 완료 ID는 키 없이 재검증·재사용한다. 미완료 ID를 자동 재전송하지 않는다. 인증·공통 설정 장애면 후속 호출을 중단하고 이미 실행한 실패·미시작을 보존한다.
- 각 원본은 새 Git 제외 private root에0600/0700으로 보관한다. 기존 archive·등록 보관본0400/0500은 편집하지 않는다. 실패도 D05에 등록하며 validated만 D06으로 투영한다. 단일 문서 source는 기존 문서 값을 그대로 파생한다.
- 구역은 영 UUID·사전 `development-unassigned`·문서별 안정 split UUID로 미배정 상태를 표시한다. 사실·geometry·검토자·검토시각을 만들어내지 않으며 draft/hidden·pending/unchecked를 유지한다.
