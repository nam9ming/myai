# 규칙 추출 기준선 설계

`docs/spec/05_시험과인수기준.md`의 규칙/AI/사람 수정후 비교 중 규칙 실행 원본을 구현한다. 기존 8필드 채점기를 그대로 사용하며 실제 확인 자료로 규칙을 조정하지 않는다.

## 범위와 경계

- Python3.13 표준 라이브러리만 사용한다. 키·AI·네트워크·DB를 사용하지 않는다.
- `rule-profile-v1`은 유형/대상/예외의 리터럴 키워드와 지명/별칭/종류를 명시한다. 버전·정확한 바이트 hash를 실행마다 보존한다. 프로필은 검토된 개발 사전을 제공받는 입력이며 도구가 검토 사실을 인증하지 않는다. 공개 예제는 합성이다.
- `rule-extract-v1`은 본문 키워드가 있는 문서마다 사건1건·일정1건을 만든다. 복수 사건/일정을 분리하지 않는 약한 기준선이다. 유형 단어가 없으면 빈 결과이며 게시일·현재 날짜·제목으로 사실을 보충하지 않는다.
- 전체 날짜(ISO, 점/슬래시 구분, 년월일)와 명시한 두 날짜 범위, `HH:mm[:ss]` 시간 범위를 지원한다. 부분 날짜·복수/충돌 범위는 null/ambiguous다. 익일은 범위 사이에 명시된 경우만 적용하며 종료가 이르면 자동으로 익일로 바꾸지 않는다. 명시 종일과 시각 미기재를 구별한다.
- 장소는 고정 사전의 리터럴 별칭으로만 찾는다. 주소·좌표를 생성하지 않는다. 대상은 키워드 주변 문장 하나, 예외는 주변 문장 목록을 보존한다. 명시한 예외 없음만 빈 배열이다. 알려진 값에는 실제 block 인용·문자 위치·SHA를 붙인다. 나머지 필드는 미상이다.
- 결과는 기존 `extract-schema-v1`으로 검증하고 `score_document`로 채점할 수 있다. 출력8MiB 초과는 `RULE_OUTPUT_LIMIT` 실패 원본으로 보관하며 조용히 잘라 성공시키지 않는다.

## 원본 보관과 CLI

`rules-run-v1`은 AI D05와 별도인 Git 제외 `data/private/rule-runs/UUID`에 입력·프로필·출력·메타데이터·identity·receipt를 보관한다. 모델/토큰/금액을 꾸미지 않는다. 파일0400/디렉터리0500·전체 hash·재계산·정확한 파일 집합을 검증한 뒤 기존 배타 rename으로 설치한다. 동일 ID/입력/프로필/전처리 버전만 재사용하고 다른 원본은 충돌이다. 실패 원본도 보존한다. 원래 입력 경로 없이 재검증한다.

`rules-run --input INPUT --profile PROFILE --preprocessing-version VERSION [--run-id UUID]`, `rules-verify UUID`를 기존 추출 CLI에 추가한다. stdout은 원문·경로·검토자 없는 receipt 요약이다. 성공0/실행실패4/입력2/보관손상·충돌3/I/O5/내부1이다. 기존 AI verify/draft는 이 형식을 수용하지 않는다.

## 후속 완료 조건

이 단계는 실행기와 재현 가능한 원본이다. D08의 `method=rules` 선택/동결 어댑터, 사람 수정값과 세 방법 비교, 실제 독립 gold·40문서 평가는 다음 단계에 남긴다. 실제 검토 지명 사전·holdout 확보·성능 수치를 만들었다고 보고하지 않는다. POSIX 권한은 관리자 변경·삭제를 막는 WORM이 아니며 Windows/전원 중단 내구성은 미검증이다.
