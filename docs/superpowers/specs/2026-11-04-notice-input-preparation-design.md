# 공식 공지 D03·AI 입력 준비 설계

## 목적·기준

G02/G06/G08의 다음 입력을 준비한다. 수집된 고유 본문47개에서 기존 개발3개를 제외한44개 전체를 대상으로, 실제 선정 본문·수신 파일·비식별화·NFC/LF와 식별자/hash를 추적한다. 기존 `source-import-v1`·D03 23키와 AI 입력5키를 유지한다. 준비 성공은 원문 완전성·이용권한·사람 확인·40건 평가 완료를 인증하지 않는다.

## 접근 선택

1. 기존 Java Reader·Python `parse_input`/`prepare`와 비공개 일회성 준비 코드를 사용한다. 공개 API·계약·의존성 변경 없이 실제 파일을 검사할 수 있어 선택했다.
2. 새 수집 서비스나 dry-run CLI는 이번 준비에 필요하지 않다. DB import를 파일 검증 대신 실행하면 쓰기까지 발생하므로 후속 단계로 둔다.

사용자가 위임한 자율 진행 범위에서 선택한 설계다. 본문 형식별 에이전트가 원문 선정을 분담하고 부모가 공통 변환·검증·Git을 맡는다.

## 입력·산출물

원본은 Git 제외 `data/private/evaluation/intake/official-notices-2026-11-04/`의 고정 manifest·index·본문 감사다. 직접 본문13개·HTML 본문13개·Markdown 잠정경계18개를 모두 대조한다. 제목·목록·chat/footer·generic ALT로 없는 본문을 채우지 않는다. 이미지/첨부에서 확인하지 않은 내용·연도·날짜·장소·관계를 추정하지 않는다. 본문이 부족하면 원인·보류를 보존하고 원문 추가 확인으로 해결하며 대상을 줄이지 않는다.

새 private `data/private/development-notices/2026-11-04-d03-preparation/`에 선정 기록·raw 바이트 복사·D03 배치·문서별 AI 입력·기존 prepare 산출물·검증 로그를 둔다. raw는 수신 표현이라는 실제 방법을 기록하며 서버 원본이라고 부르지 않는다. 원본 파일은 변경하지 않고 복사 후 SHA를 대조한다. 파일0600·디렉터리0700, 새 파일만 생성하고 충돌 시 덮어쓰지 않는다. 리뷰에서 발견한 URL 숫자 매개변수 오치환은 전처리 v2로 수정하며, 최종 `package-v2/`와 이를 가리키는 `current-preparation.json`을 사용한다. 초기 `package/`는 재현용으로만 보존하고 등록에 사용하지 않는다.

본문·제목을 NFC/LF로 정리한다. 본문에서 관찰한 전화/이메일 패턴은 고정 표시로 치환하고 정규화 전후/비식별화 hash·제거 범주와 위치만 기록한다. 제거값은 로그·프롬프트에 남기지 않는다. 공개 행사 인물명이나 날짜·시간·노선·금액을 임의 변형하지 않으며 자동 패턴 밖 개인정보 검토는 미완료로 남긴다. 비어 있지 않은 원래 행 순서를 블록으로 유지하고 cleaned_text의 실제 부분문자열로 대조한다.

게시판/게시ID 기준 신규 문서에 안정 UUID를 배정한다. 기존3건·별칭·검색전용1건은 새 문서로 만들지 않는다. 같은 입력 재생성의 ID는 같고 다른 게시물은 다르다. `version_no=1`, `official_number=null`, `use_review=pending`, `checks=[]`, 확인 시각null·`check_result=unchecked`를 사용한다. 게시일·수집 UTC는 같은 관찰의 실제 제공값을 사용한다. 이 준비는 기존 DB의 중복/다음 버전 번호를 확인하지 않는다.

## 검증·경계

작은 RED→GREEN 시험으로 정규화·연락처 치환·날짜/노선 보존·빈/제목 대용 본문·식별/경로/기존 파일 충돌을 확인한다. 기존 Java `ReviewedImportReader.read`와 Python `parse_input`를 실제 배치44개에 적용하고 원래 블록 전체 투영을 대조한다. Java는 기존 앱 클래스·고정 JAR 의존성을 재사용한 비공개 실행기로 Reader만 호출하며 Spring/DB를 기동하지 않는다. raw/text hash 손상 음성 대조군을 사용한다.

Python `prepare`의 실제44회 산출물·input/prompt hash와 상태를 대조한다. 로컬 키·외부 추출 API·DB 등록·D05/D06·사건/구역·분할·gold·D09·사람 승인·main/배포를 새로 생성/실행하지 않는다. 작성자 전체 검토와 새 문맥 전체 리뷰 후 원격 CI/자동 리뷰·develop 통합 검증을 완료한다.
