# 여기:it Flutter Web 화면 작업

[현행 업무] 이상헌: 화면 검토·확정과 Flutter 구현. 김윤기: 화면별 필드·API·오류 합의와 백엔드 연동. 명묵: 반복 시나리오 검증. 남규민: 우선 분야·수집처·개인화·일정 범위 합의. 각 단계 완료 예정일은 팀과 정하며 임의 날짜로 확정하지 않습니다.

[확정 요구] 안성시민 전체의 교육·배움 / 지원·혜택 / 행사·문화 / 공사·교통 / 생활정보를 다루고 기존 소상공인 조건 선별을 유지합니다. 특정 집단의 초기 검증을 전체 서비스의5지점·500m·14일 제한으로 바꾸지 않습니다.

## 화면·연동 보존 기준

- Flutter stable·Dart 프로젝트를 `frontend/`에 구성하고 버전·의존성을 고정합니다. 현재 저장소에는 Flutter 코드가 없습니다.
- 기존 공사/행사/교통, 후보/확인 필요/취소, 대상·예외·원문·게시일·확인 시각을 보존합니다. 새5분야 enum·필드·경로는 합의·계약 보완 후 구현합니다.
- 상세는 대상·자격/신청조건·방법·준비사항·비용·지역·원문과 확보된 변경 전후·확인시점을 표시합니다. 없는 이력은 미확인, 비용 누락은 미상으로 두고 연령·관심만으로 자격을 확정하지 않습니다. 신청 마감을 진행 종료로 표시하지 않습니다.
- `LayoutBuilder` 등으로 모바일 한 열·PC 가독성을 구성합니다. 주요 조작44 logical px 이상, 긴 글 줄바꿈·확대·키보드/초점·`Semantics`·빈결과·로딩·실패/재시도를 확인합니다.
- 브라우저 뒤로가기·새로고침·상세 직접 진입·조건/필터 복원을 구현합니다. 원문은 사용자 클릭으로 열고 실패 시 URL 확인/복사 수단을 제공합니다.
- 서버 UTC→Asia/Seoul 표시는 공통 유틸리티로 처리하고 기존 시간·거리·후보 판정을 Dart에서 재계산하지 않습니다. Python code point 근거 offset을 Dart UTF-16 인덱스로 바로 사용하지 않습니다.
- API URL·base path를 설정으로 분리합니다. Flutter 코드/manifest·클라이언트 설정에 비밀키를 넣지 않으며 실제 사용자 조건을 서버 영구 수집하지 않습니다.
- S10은 동등한 로컬 HTML 보고서·명령 방식으로 인수할 수 있습니다. 별도 관리 UI를 시민 화면 연동의 새 필수 조건으로 추가하지 않습니다.

[합의 필요] 차별화 후보3개는 모두 수용하는 원칙이며 정확한 명칭·내용을 확인해야 합니다. 정보분석·개인화·이해지원·신뢰성4항목은 구체화 제안이며3후보를 대체하거나 확정하지 않습니다.
