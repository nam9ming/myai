# Flutter Web 화면 작업

담당: 이상헌 · 첫 결과: **11/3(화) 오후6시(KST)** · 연구실 PC 시연: **11/4(수), 시각미정**

- Flutter stable·Dart 웹 프로젝트를 `frontend/`에 구성하고 버전·의존성을 고정합니다.
- 모바일 정보 서비스 참고를 빠르게 좁혀 디자인 방향1개를 고르고 목록 화면부터 적용합니다. 기존 연한 초록/회색 HTML의 색·배치는 확정 디자인이 아닙니다.
- 공지 목록 S02→상세 S03→가게 조건 S01 순으로 구현하고 최종 시연은 조건→목록→상세·근거→원문으로 연결합니다.
- 공사/행사/교통, 후보/확인 필요/취소, 대상·예외·원문·게시일·확인 시각을 보존합니다.
- 같은 DTO/화면을 공통 JSON fixture와 Spring API에 사용합니다. 기본 네트워크 계층을 한곳에 모으고 예제/실제 모드를 화면에 구분합니다.
- LayoutBuilder 등으로 모바일 한 열·PC 가독성을 구성합니다. 주요 조작44 logical px 이상, 긴 글 줄바꿈·확대·키보드/초점·Semantics·빈결과·로딩·실패/재시도를 확인합니다.
- 브라우저 뒤로가기·새로고침·상세 직접 진입·조건/필터 복원을 구현합니다. 원문 링크는 사용자 클릭에서 열고 열기 실패 시 URL 확인/복사 수단을 제공합니다.
- 서버 UTC→Asia/Seoul 표시는 공통 유틸리티로 처리하고 시간·거리·후보 분류를 Dart에서 재계산하지 않습니다. Python code point 근거 offset을 Dart UTF-16 인덱스로 바로 사용하지 않습니다.
- API URL·base path를 설정으로 분리하고 웹 빌드 폴더 전체를 남규민에게 인계합니다. Flutter 코드/manifest·클라이언트 설정에는 비밀키를 넣지 않습니다.

오후6시에는 예제 데이터로 조건·목록·상세·원문이 이어지는 실행 버전, 캡처, 설치·실행·빌드 명령을 전달합니다. 참고 화면 조사나 빈 화면만으로 완료 처리하지 않습니다. [화면 시연 작업 기준](../docs/wednesday-screen-brief.md)을 함께 적용합니다.
