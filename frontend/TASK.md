# 수요일까지: 디자인 방향을 정하고 핵심 동선을 구현

담당: 이상헌 · 목표일2026-11-04

- 실제 모바일 정보 서비스의 참고 화면을 빠르게 비교하고 추천 방향1개를 정합니다. 참고 캡처·출처·적용 요소를 남기되 조사만 하다가 구현이 늦어지지 않게 합니다.
- 가게 조건 → 공지 목록 → 조건/근거 상세 → 원문 동선을 구현합니다. 목록부터 디자인 방향을 공유하고 조건·상세에 확장합니다.
- 공사/행사/교통 유형, 후보/확인 필요/취소, 대상/예외, 게시일/확인 시각, 원문 버튼을 보존합니다.
- 먼저 contracts의 가상 예제로 동작하게 만들고 같은 형식의 백엔드 API로 교체합니다. API 필드명/상태를 프런트에서 새로 정의하지 않습니다.
- 모바일 한 열, 주요 조작44px 이상, 읽을 수 있는 글자 대비/크기, 긴 문구 줄바꿈, 빈 결과/실패/재시도를 고려합니다.
- `/myai/team/` 하위 배포를 전제로 자산/API 경로를 한곳에서 설정하게 합니다. 실제 운영 서버는 수정하지 않습니다.

완료 기준: 휴대폰 크기에서 조건 변경→목록 갱신→상세→원문이 이어지고, 사용한 데이터가 가상/실제 중 무엇인지 알 수 있습니다. 설치/실행 방법·현재 연결 상태·미완료를 README에 남깁니다.
