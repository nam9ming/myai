# 내 주변 지도와 교체 가능한 자료

지도는 헤더·분야 탭·푸터 없이 전체 화면으로 표시한다. 하단 내비게이션은 유지한다. 마커 선택 시 하단 시트가 40% 높이로 열리며 위로 끌면 86%, 아래로 끌면 16%로 접힌다. 시트 안에서 내용과 원문을 확인한다. 드래그 대신 `올려서 보기`·`접기` 버튼도 제공하며 모션 감소 설정을 따른다. 시트와 상단 패널의 터치는 native 지도에 전달되지 않게 별도 플랫폼 층으로 분리한다.

하단 기존 네 메뉴 사이에 `내 주변`을 추가했다. PC는 상단 위치 아이콘으로 연다. 주소는 `#/nearby`, 선택 소식 직접 링크는 `#/nearby?id=소식ID`다. 카카오 지도의 기존 SDK 브리지·캐릭터 자산을 재사용하고 지도 코드와 SDK는 해당 화면 진입 때만 로드한다. 초기 홈의 폰트·엔진 최적화는 유지한다.

## 데이터만 교체하는 방법

기본 `web/nearby-feed.json`은 안성 주변 창작 예시 8건이다. `data_kind=demo`를 화면의 작은 `예시` 표시에 반영한다. 실제 공지로 오인하지 않도록 일정·내용에 예시임을 기록했다.

**방법 A — 파일 교체:** 같은 형식의 실제 JSON을 준비해 배포 폴더의 `nearby-feed.json`을 교체한다. 앱 재빌드는 필요 없다. 화면을 다시 열거나 `새로고침`을 누르면 읽는다. 교체 전 파일을 백업하고 임시 파일에 쓴 뒤 rename으로 교체한다. 향후 앱 배포에서도 유지하려면 원본 `web/nearby-feed.json`도 함께 관리하거나 방법 B를 사용한다.

**방법 B — API/별도 파일 연결:** 배포 폴더의 `nearby-config.json`을 다음처럼 설정한다. 이후 서버가 같은 JSON을 반환하면 앱 수정 없이 연결된다.

```json
{"url":"/team_asai1/data/nearby.json"}
```

이 경로는 연결 형식 예시이며 실제 서버에 새 경로나 백엔드 API를 만들었다는 뜻이 아니다. API도 동일한 URL 설정으로 GET 조회한다. 인증정보를 URL이나 JSON에 넣지 않는다. 현재 CEHUB CSP의 연결 허용 범위 `/team_asai1/` 안에서 제공하고 opaque sandbox의 공개 조회를 허용하는 CORS가 필요하다. 외부 API는 기존 승인된 팀 서버가 공개 자료를 반환하도록 연결해야 한다. 공용 CSP·인증 경계를 완화하지 않는다.

수집 서버는 검토·공개 가능한 자료를 아래 형식으로 내보내면 된다. **브라우저가 특정 기관 웹사이트를 임의 크롤링하는 기능은 아니다.** 실제 수집처·HTML 구조·공개 절차가 아직 없으므로 특정 사이트 수집기를 추정해서 넣지 않았다. 기존 Spring 계약·Python 거리/시간/후보 판정도 변경하지 않았다.

## JSON 형식 v1

```json
{
  "version": 1,
  "data_kind": "live",
  "updated_at": "2026-11-17T05:00:00Z",
  "items": [
    {
      "id": "공개자료의-고유ID",
      "category": "event",
      "title": "공개된 소식 제목",
      "lat": 37.0069,
      "lng": 127.2721,
      "address": "검토된 행사 장소",
      "description": "공개된 내용과 확인이 필요한 조건",
      "start": "2026-11-20",
      "end": "2026-11-21",
      "status": "scheduled",
      "source_url": "https://공식기관.example/개별공지"
    }
  ]
}
```

위 JSON은 형식 설명용이며 실제 자료가 아니다. `live`에는 실제 개별 공지 원문 주소를 넣는다. 기관 홈페이지를 개별 공지 원문으로 대신하지 않는다.

- `data_kind`: `demo` 또는 `live`. `updated_at`: ISO 시각. API는 갱신 시각을 실제로 기록한다.
- `category`: `education`, `support`, `event`, `traffic`, `life`.
- `status`: `scheduled`, `ongoing`, `cancelled`, `unknown`. 취소를 지도와 카드에서 보존한다. 일정을 임의로 계산해 운영 상태를 확정하지 않는다.
- 좌표는 WGS84 숫자 `lat`(-90~90), `lng`(-180~180). 위치 미확인 소식은 이 지도 피드에 넣지 않는다. 주소를 임의 중심점으로 지오코딩하지 않는다.
- `start`/`end`는 YYYY-MM-DD 또는 null. 종료가 시작보다 빠르면 오류다. 모르는 일정은 null이며 신청 마감과 진행 일정을 혼동하지 않는다.
- `source_url`: 공개 http/https 개별 공지 URL. `live`에서 필수이며 `demo`에서는 null 허용.
- 피드는 최대 100건·응답 문자열 1,000,000자. 중복 ID·잘못된 좌표·출처·버전·형식은 오류로 처리한다. 더 많은 자료는 서버의 공개 피드 범위를 정하거나 페이지/영역 조회 계약을 별도로 확장해야 한다. 조용히 앞 100건만 자르지 않는다.

카드 목록은 현재 지도 영역과 분야에 따라 바뀐다. 지도 이동은 공개 피드를 다시 긁거나 기존 계산 API를 호출하지 않는다. 화면 진입과 명시적 새로고침에서 설정·자료를 다시 GET 조회한다. 목록에 전체가 내려와도 거리·신청 자격·영업 영향은 추정하지 않는다.

## 실패·위치·보안

실제 조회 실패·형식 오류는 오류 화면과 다시 조회로 처리한다. 이전 마커와 카드를 제거하며 예시로 자동 대체하지 않는다. 0건은 정상 빈 목록이다. 원문은 사용자 클릭에서만 열며 HTML 문자열로 자료를 삽입하지 않는다.

현재 위치는 지도 안의 `내 주변 보기`를 누를 때만 요청한다. 좌표는 지도 중심·현재 위치 표시에만 쓰며 저장하거나 피드 서버에 전송하지 않는다. 거부·시간 초과에는 지도 직접 탐색을 유지한다. 기본 지도는 안성이다. 선택한 다른 도시의 실제 자료라고 표시하지 않는다.

키는 저장소 밖의 `.config/myai/kakao-maps.env`에서 기존 `scripts/inject-kakao-key.py`로 **생성된 빌드에만** 주입한다. 키 원본·REST/Admin 키는 웹 자산에 넣지 않는다. JavaScript 키의 CEHUB 도메인 제한은 유지한다. 공개 전 SDK 로드·타일·마커와 기존 흐름을 실제 HTTPS에서 검사한다.

## 검증

```sh
flutter test test/nearby_test.dart test/screens_test.dart
python3 scripts/inject-kakao-key.py --check # 저장소 루트에서 실행
```

단위 검사는 예시→실제 스키마 교체, 좌표·중복·원문·버전 오류와 정상 0건을 확인한다. 위젯 검사는 중앙 메뉴·카드 선택·조회 실패를 확인한다. 브라우저에서는 실제 SDK·지도 지연 로딩·8마커·선택·권한 거부·실제 형식 전환(모의 공개 응답)·503 오류·복구를 검사한다. 모의 응답 전환을 실제 시민 자료 연동으로 기록하지 않는다. 물리 iPhone 카카오톡 GPS는 별도 검수다.

## 지도 목록과 상세 화면

예시는 30건이며 각 분류에 6건씩 있습니다. `summary`는 선택 필드이며 240자 이내의 짧은 설명입니다. 생략하면 본문에서 요약을 가져옵니다. 시트 카드를 누르면 `/nearby/detail?id=...`에서 전체 설명을 봅니다.

지도에는 별도 위치·확대·축소·안성·전체 버튼을 두지 않습니다. 지도 기본 제스처로 이동합니다. 시트를 펼쳐도 조회 범위를 유지하고, 가장자리 아이콘을 포함하도록 범위에 여백을 둡니다. 선택한 소식은 목록 위에 유지합니다.
