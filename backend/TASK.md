# 수요일까지: 저장·선별·조회 API를 연결

담당: 강명묵 · 목표일2026-11-04

**첫 결과 인계: 11/3(화) 오후6시(KST).** 서버 실행과 config·matches·events 3개 API의 첫 연결 버전, 예제 응답·검토본 저장/불러오기 방법, 실행 명령과 미구현 규칙을 인계합니다.

수요일은 연구실 개발환경에서 PC 브라우저로 시연합니다. 모바일 우선 반응형 설계와 전체 기능 목표는 유지합니다. 우선 [화면 시연 작업 기준](../docs/wednesday-screen-brief.md)을 확인합니다.

- `GET /api/v1/config`, `POST /api/v1/matches`, `GET /api/v1/events/{id}`를 계약/예제에 맞게 구현합니다.
- 프런트와 첫 연결은 contracts의 가상 예제로 시작할 수 있습니다. 이후 AI 담당의 **사람 검토본**을 저장·읽는 경로를 연결합니다.
- 수동 수집·일괄 처리·검토 파일 저장은 기존 명세의 구현 선택지입니다. 저장 방식을 명시하고 DB를 쓴다면 모델/수정/공개 경계를 남깁니다.
- 시각은 UTC 저장/반환·KST 표시 원칙, 오늘 포함14일·500m·영업 중첩, 미상/취소를 구분합니다. 전체 예외 규칙은 docs/spec/04를 따르고 미실행/미구현은 명시합니다.
- 데이터가 없는 상태와 조회 실패를 구분하고 입력 검증·알 수 없는 ID·오류 응답을 정의합니다.
- 공개 API에 AI 키·원문 비공개 경로·실제 평가 기록이 섞이지 않게 합니다. 공개 웹에 팀 관리 도구를 그대로 노출하지 않습니다.
- 하위경로 연결은 실제 프록시 구성을 확인한 뒤 팀장과 합의합니다. 기존 연구실 서버 설정은 수정하지 않습니다.

완료 기준: 프런트가 합의한 요청을 보내면 일관된 응답을 받고, 저장 데이터/가상 예시/미상/오류가 구분됩니다. AI 실행 자체를 사용자 조회의 필수 대기 조건으로 만들지 않습니다.
